# Open Bandit Dataset → GrowthEvo Locked OPE

GrowthEvo keeps Open Bandit tooling **optional**. The default runtime remains dependency-free, while a maintained OBP distribution can be installed only for real OBD export/integration work.

Two execution modes are supported:

1. **Modern same-environment mode (recommended on Python 3.11/3.12):** install GrowthEvo with the `obd` extra, which pins `sb-obp==0.5.10`.
2. **Process-isolated mode:** run the standalone exporter in any separate OBP-compatible environment and pass its JSONL outputs into a normal GrowthEvo environment.

The exporter itself remains standalone and imports `obp`, sklearn, and numpy only when it is actually executed.

## Why Open Bandit Dataset

Open Bandit Dataset contains logs generated by multiple production policies on the same ZOZOTOWN platform. The official OPE evaluation protocol uses one policy's log as off-policy evaluation evidence and another policy's factual rewards as an on-policy reference. This makes OBD unusually suitable for evaluating estimation error rather than only reporting an unverified OPE point estimate.

The exporter currently implements the canonical `random → BernoulliTS` direction from the official quickstart.

## Recommended environment

On Python 3.11 or 3.12:

```bash
pip install -e '.[obd]'
```

The extra currently pins the maintained `sb-obp==0.5.10` release, which provides the `obp` Python namespace and supports Python 3.11/3.12. It is deliberately not a default dependency because the production/runtime harness does not need pandas, sklearn, torch, or the rest of the OPE research stack.

For another OBP-compatible environment, no GrowthEvo installation is required to run the exporter itself; copy/use `scripts/export_obd_locked_ope.py`, then move the generated JSONL and manifest into the GrowthEvo environment.

## Export command

```bash
python scripts/export_obd_locked_ope.py \
  --campaign all \
  --output-dir /tmp/growthevo-obd-all \
  --validation-fraction 0.5 \
  --n-sim 100000 \
  --q-folds 3 \
  --q-model logistic \
  --random-state 12345
```

If the full OBD has been downloaded manually, provide its root with:

```bash
--data-path /path/to/open_bandit_dataset
```

### Outputs

The exporter writes:

- `validation.jsonl`
- `holdout.jsonl`
- `ope_candidates.json`
- `export_manifest.json`

The JSONL files conform exactly to `growthevo-locked-ope`.

## Target-policy probability

The exporter reconstructs the production BernoulliTS policy using the OBP interface and Monte Carlo action distribution:

```text
BernoulliTS(
    is_zozotown_prior=True,
    campaign=<campaign>
).compute_batch_action_dist(...)
```

For each factual row `i`, action `a_i` and position `p_i`, GrowthEvo receives:

```math
\pi_e(a_i\mid x_i,p_i)
=
\mathrm{action\_dist}[i,a_i,p_i].
```

The exporter verifies that target-policy probability mass sums to one for every exported row/position.

## Q terms for DM / DR / DR-OS

With `--q-model logistic` (default), each chronological evidence window independently calls `RegressionModel.fit_predict(..., n_folds=K)`. Thus validation Q predictions do not learn from holdout rewards, and holdout Q predictions do not learn from validation rewards.

For the factual action:

```math
\widehat q_i
=
\widehat Q_i(a_i,p_i).
```

For the target-policy expected reward term:

```math
\widehat q_{\pi,i}
=
\sum_a
\pi_e(a\mid x_i,p_i)\widehat Q_i(a,p_i).
```

These become GrowthEvo's `baseline_q` and `target_q` respectively.

`--q-model zero` exists only for integration/IPS/SNIPS/β*-IPS debugging. A zero-Q export must **not** be used to claim DM, DR, SWITCH-DR, DR-OS, or Meta-OPE performance. GrowthEvo CI intentionally uses zero-Q in the public small-OBD smoke because that job verifies the external API/data path rather than estimator accuracy.

## Paired chronological validation and holdout

GrowthEvo needs a validation cohort for estimator/hyperparameter selection **before** final holdout evaluation. The exporter therefore creates two non-overlapping chronological windows for both production policies:

- earlier random-policy rows → validation OPE evidence;
- earlier BTS factual rows → validation on-policy reference;
- later random-policy rows → final holdout OPE evidence;
- later BTS factual rows → final holdout on-policy reference.

The split fraction is fixed by `--validation-fraction` before estimator selection.

This is a GrowthEvo locked-selection extension of the official two-policy OPE idea. It should not be mislabeled as the exact historical OBP benchmark protocol; `export_manifest.json` records the paired-window definition explicitly.

## Stable row identity

Each random-policy row receives an identity containing:

- behavior policy;
- campaign;
- raw CSV index;
- timestamp;
- factual item;
- factual position;
- sorted-data ordinal.

The locked runner rejects validation/holdout identity overlap.

The exporter does **not** invent a default cluster ID. A cluster-robust standard error should only be requested after the experiment defines a defensible cluster/block unit.

## Locked evaluation

After export:

```bash
growthevo-locked-ope \
  --tuning-jsonl /tmp/growthevo-obd-all/validation.jsonl \
  --test-jsonl /tmp/growthevo-obd-all/holdout.jsonl \
  --candidates-json /tmp/growthevo-obd-all/ope_candidates.json \
  --tuning-reference <validation_reference_from_manifest> \
  --test-reference <holdout_reference_from_manifest> \
  --benchmark open-bandit-ope \
  --dataset obd-all-random-to-bts \
  --commit-sha "$(git rev-parse HEAD)" \
  --output benchmark-result.json
```

Only the estimator/hyperparameter configuration selected on the validation reference reaches the final holdout reference.

## Default candidate grid

The exporter emits a finite, predeclared grid containing:

- cross-fitted β*-IPS;
- Doubly Robust;
- IPS;
- SNIPS;
- two SWITCH-DR thresholds;
- two DR-OS shrinkage values;
- Meta-OPE/BLUE diagnostic.

The grid is intentionally small. Expanding a hyperparameter grid after inspecting validation or holdout results is adaptive selection and must be documented as a new protocol.

## CI integration smoke

The dedicated Python 3.12 CI job installs `.[obd]`, clones the public small OBD, exports real `all/random → BTS` evidence with a low Monte Carlo count and zero Q, and runs the resulting files through `growthevo-locked-ope`.

This job verifies:

- the maintained OBP package still imports under the supported GrowthEvo interpreter;
- public OBD file layout is compatible with the exporter;
- production BernoulliTS replication still exposes the expected action-distribution shape;
- action/position mapping reaches GrowthEvo correctly;
- the locked runner can consume a real OBD export and emit a valid artifact.

It is an **integration smoke**, not a performance benchmark.

## Full-data promotion

The 10,000-row-per-policy example OBD is useful for pipeline verification, but it is not a replacement for a full-data benchmark claim. README performance promotion should use the full research release where practical, `--q-model logistic` (or another predeclared cross-fitted reward model), and must archive:

- `export_manifest.json`;
- exact candidate JSON;
- validation scoreboard;
- locked holdout artifact;
- code commit SHA;
- dataset release/source identity.
